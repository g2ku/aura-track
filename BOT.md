# Telegram-бот накладных

Баристы пишут накладные в группу обычным текстом — бот разбирает их,
складывает в Firestore и вечером присылает сводку за день.

Данные пишутся в ту же коллекцию `documents`, что и загрузка Excel-накладных
на сайте, поэтому **всё, что принял бот, сразу видно в веб-интерфейсе** —
Дашборд, Филиалы, Отчёты. Отдельная интеграция не нужна.

## Как это выглядит для бариста

```
Абая
Пончики - 48шт - 40000
Круассан 20шт 15000
```

Бот отвечает подтверждением — что именно он понял:

```
✅ Абая — принято
• Пончики — 48 шт — 40 000 ₸
• Круассан — 20 шт — 15 000 ₸
Итого по накладной: 55 000 ₸
Всего по точке за день: 55 000 ₸
```

Филиал можно сокращать: `абая`, `гаг`, `жар`, `оби`, `кок`, `дуб`, `атак`, `рамс`.

Точку, которую в чатах зовут **Бауманская/баума**, бот понимает как **Дубай** —
так она называется на сайте и в Poster. Писать можно как привычно.
Суммы: `40000`, `40 000`, `40.000`, `40к`, `40к тенге`.

На обычные сообщения в группе бот **молчит** — реагирует, только если узнал
филиал или получил команду.

## Команды

| Команда | Что делает |
|---|---|
| `/отчет` | Сводка за сегодня |
| `/отчет 2026-08-14` | Сводка за конкретный день (можно `14.08.2026`) |
| `/отчет вчера` | За вчера |
| `/отчет 14 дней` | За период: `неделя`, `2 недели`, `месяц`, `30 дней` |
| `/отчет 2026-08-01 2026-08-14` | За явный диапазон дат |
| `/отмена` | Убрать свою последнюю накладную |
| `/филиалы` | Список филиалов и сокращений |
| `/помощь` | Справка по формату |

Админские:

| Команда | Что делает |
|---|---|
| `/админ` | Назначить себя администратором (первый раз — доступно всем) |
| `/настройки` | Показать текущие настройки |
| `/подключить` | Принимать накладные из этого чата |
| `/отключить` | Перестать принимать накладные отсюда |
| `/чаты` | Список подключённых чатов |
| `/сюда` | Слать автоотчёт сюда — работает и в личке |
| `/пауза` / `/продолжить` | Приостановить и возобновить приём |
| `/время 21:00` | Время автоотчёта (Алматы) |

### Несколько чатов

Бот работает в любом количестве чатов одновременно — например, отдельный
чат на «Коктем и Атакент» и общий чат сети. В каждом нужно один раз
выполнить `/подключить`. Накладные из всех чатов складываются в **один**
дневной отчёт по сети.

Отчёт можно получать отдельно от чатов приёма: напиши боту `/сюда`
в личные сообщения — сводка будет приходить только тебе.

### Поздние поставки

Если накладная придёт уже после того, как ушёл вечерний отчёт, бот
пришлёт обновлённый отчёт с пометкой «Поздняя поставка» — туда же, куда
отправляет автоотчёт. Так картина дня не остаётся неполной.

## Установка

**1. Создать бота**

Написать [@BotFather](https://t.me/BotFather) → `/newbot` → получить токен.
Там же `/setprivacy` → **Disable** — иначе бот не увидит сообщения в группе.

**2. Сервисный аккаунт Firebase**

Firebase Console → Project Settings → Service accounts → Generate new private key.
Полученный JSON нужно превратить в одну строку:

```bash
node -e "console.log(JSON.stringify(require('./путь-к-ключу.json')))" | pbcopy
```

**3. Переменные окружения на Vercel**

Project Settings → Environment Variables:

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | любая случайная строка |
| `FIREBASE_SERVICE_ACCOUNT` | JSON из шага 2 (одной строкой) |

**4. Задеплоить и подключить вебхук**

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://<домен>/api/tg/webhook&secret_token=<СЕКРЕТ>"
```

**5. Привязать чаты**

Добавить бота в группу с накладными и написать там `/админ`, затем
`/подключить`. Повторить `/подключить` в каждом чате, откуда пойдут
накладные.

Куда слать вечерний отчёт — задаётся командой `/сюда`: в нужной группе
или в личке боту.

Проверить: `/отчет` должен ответить сводкой.

> Если ты админ группы с включённой анонимностью, Telegram передаёт боту
> не твой id, а служебный `1087968824` (@GroupAnonymousBot). Тогда
> админ-команды сработают только при анонимной отправке. Чтобы записался
> личный id — выключи анонимность и выполни `/админ` ещё раз.

## Автоотчёт

Cron в `vercel.json` дёргает `/api/tg/report` раз в сутки в 16:00 UTC —
это 21:00 в Алматы. Такое расписание работает на любом тарифе Vercel.

Отчёт уходит по правилу «сегодня ещё не отправляли и время из `/время`
уже наступило», а не по точному совпадению часа. Поэтому он не теряется,
если cron сработал с задержкой, и не дублируется при повторном запуске.

Если тариф Pro и хочется, чтобы `/время` срабатывало точно в заданный час —
поменяй расписание на `"0 * * * *"` (ежечасно), логика к этому готова.

Ручной запуск отчёта: `GET /api/tg/report?force=1` (обходит обе проверки).

## Тесты

```bash
node test-tg-parser.mjs && node test-tg-report.mjs && node test-tg-bot.mjs
```

Все три работают офлайн — без Telegram и без Firestore.

## Устройство

```
api/_lib/branches.js   справочник филиалов и сокращений
api/_lib/tgParser.js   разбор текста накладной
api/_lib/dailyDoc.js   накопление за день + формат отчёта
api/_lib/store.js      Firestore (транзакции) и настройки
api/_lib/telegram.js   обёртка над Telegram API
api/_lib/commands.js   поведение бота (тестируется без сети)
api/tg/webhook.js      точка входа
api/tg/report.js       автоотчёт по расписанию
```

Логика отделена от транспорта: `commands.js` получает хранилище параметром,
поэтому в тестах подставляется поддельное — и всё поведение бота проверяется
без реальных сервисов.

## Известные ограничения

- **`Пончики 20 500` без «шт»** разбирается как сумма 20500, а не «20 шт по 500» —
  это неоднозначно и для человека. Защита: бот всегда отвечает тем, что понял.
- **Повторная накладная суммируется**, а не заменяет предыдущую — за день с
  точки может прийти несколько поставок. Ошибку убирает `/отмена`.
- **Одно сообщение — один филиал.** Если в сообщении несколько точек, бот
  возьмёт первую и предупредит.

## Что дальше

Автозапись в Poster намеренно **не сделана**: это необратимая операция.
Разумный порядок — месяц накапливать данные ботом и сверять с Poster вручную,
и только потом включать автозапись, уже зная реальное качество распознавания.
