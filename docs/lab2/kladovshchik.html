1.2Инструменты

Стек без своего сервера и без админа

Клиент
  • React 18 и Vite 5
  • Zustand — состояние, Chart.js — графики
  • Telegram Mini Apps: своя сборка для «Расходников»
  • Импорт накладных из Excel и PDF
Сервер
  • Node.js, serverless-функции на Vercel
  • Telegram Bot API через вебхук
  • Проверка токена и подписи Mini App на node:crypto
Данные
  • Cloud Firestore и Firebase Auth
  • API POS-системы (Poster): продажи, склады, поставки
  • Транзакции: выдача пишется целиком или никак
Качество
  • ~5 300 автоматических проверок в 55 файлах
  • Логика отдельно от сети — тесты без Telegram и базы
  • Git и GitHub, деплой на каждый push
1Архитектура

Три входа, пять групп серверных функций, база и POS

Рисунок 1. Клиенты не ходят в POS напрямую: токен POS живёт только на сервере. Браузер читает журнал накладных и роли из Firestore напрямую, по правилам доступа.

1.3 · UMLПролог · варианты использования

Кто пользуется системой и зачем

Рисунок 2. Четыре роли людей и две внешние системы. Владелец наследует всё, что может управляющий, но по всей сети; управляющий видит только свою точку.

1.3 · UMLОсновной функционал · накладная

Накладная из чата попадает в журнал

Рисунок 3. Повторную доставку того же сообщения Telegram отсекает markUpdateSeen. Распознанная накладная получает ✅ на сообщении; нераспознанная — вопрос-уточнение в чат.

1.3 · UMLОсновной функционал · расходники

Снабженец записывает выдачу у машины

Рисунок 4. Запись сначала ложится в очередь на телефоне и уходит, когда появится связь. opId делает повтор безопасным: одна выдача не спишется со склада дважды.

1.3 · UMLОсновной функционал · сайт владельца

Сайт получает данные POS через прокси

Рисунок 5. Браузер предъявляет ID-токен Firebase; прокси проверяет подпись и срок и только потом ходит в POS со своим токеном. Прошлые дни берутся из кэша, сегодняшний — всегда свежий.

1.3 · UMLДоп. функции · сторож

Сторож проверяет сеть каждые 15 минут

Рисунок 6. Одна тревога приходит один раз: журнал отправленных — в Firestore. Утром — сводка с разбором «почему ниже обычного», ночью — итоги дня для быстрых ответов.

1.3 · UMLДоп. функции · ассистент

Ассистент отвечает на вопросы о продажах без платных моделей

Рисунок 7. Вопрос разбирают правила: метрика, период, точка, операция. Не понял — предлагает варианты; упал POS — говорит понятно и предлагает спросить ещё раз.
